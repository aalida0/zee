# Collection and restart

Run each shard with `python -m module14.scan worker --shard SHARD --output RESULT --receipt RECEIPT --config CONFIG`. Add `--resume` to reuse an intact result and receipt with matching input, settings and worker code. Existing destinations are never overwritten. If a run stopped after publishing only one file, keep it for inspection and restart that shard with new output and receipt paths.

Collect with `python -m module14.collect --manifest MANIFEST --config CONFIG --part SHARD RESULT RECEIPT --output REPORT`. Repeat `--part` for each completed shard. Use the same `--families` and `--perturbativity-limit` as the worker. The collector validates full manifest rows and receipts against the submitted shard and result files. An incomplete manifest yields an `INCOMPLETE` report and exit code 2; corrupt, duplicated or unexpected inputs raise an error. Cutflows cover evaluated scalar points; missing manifest points are counted separately. Neutrino NOT_EVALUATED counts are family slots, including both scalar failures and unknowns that did not reach the inverse solver.

The index is disk-backed and scales with manifest size; result and shard files are read incrementally. Wall and CPU times are summed over receipts and peak memory is the maximum worker RSS. Receipts attest to bytes and settings, not to an independently verified source bundle or runtime environment.

Optional scalar caching: add `--cache-dir DIRECTORY` to the worker. Entries bind the scalar record, scalar source files, numerical settings, Python, numerical-library versions, NumPy build and thread settings. Corrupt entries stop the worker; move the affected cache aside before retrying. The cache is useful when rerunning scalars, not necessary for a single pass. Cache directories are not transferred by the Condor template.

To prepare an unsubmitted batch, run `python module14/condor/prepare.py --commit COMMIT --config CONFIG --shard SHARD [--shard SHARD ...] --output NEW_DIRECTORY`. The output contains a Git archive, checksum, submit template and shard list. The wrapper verifies the archive and records its commit, digest and runtime in the receipt. Collection can require these using `--source-commit` and `--source-bundle-sha256`. Review the site's Python/dependency environment, file transfer, resource requests and retry policy before submission; none has been verified on a remote pool. The template currently uses the worker defaults of two families per ordering and the default perturbativity limit. Output remaps include cluster and process IDs so independently submitted retries do not overwrite prior results; select only one completed result for each shard when collecting.

The worker evaluates D4 charged-Higgs decays for each successfully reconstructed neutrino family and stores them in `widths`. It computes nonleptonic channels once per scalar, then uses each family's actual F, Ye and Ye2 for leptonic channels. PASS denotes the complete D4 on-shell tree two-body inventory, using its fixed SM input card; off-shell and loop channels are outside this result. Missing or invalid calculations remain NOT_EVALUATED or ERROR. A scalar vacuum UNKNOWN remains UNKNOWN even when its decay calculation succeeds.
