## Decisive conflict

The supplied `NEUTRAL_YUKAWA_ORDERED_MAPPING.md` asserts that native `D[e,mu]` equals the source coupling `rho_l[2,1]*sqrt(2)` conjugated and therefore enters source **c_R**. But frozen `module3/core.py::vertices` explicitly defines its native matrix through `L = -S bar(e)_a [C_ab P_L + C_ba* P_R] e_b` and identifies D's row as right-Weyl; frozen `module4/amplitudes.py::ledger` routes the same `C[e,mu]` into **C_L**. Both dipole actions label their projectors on the incoming muon. The source-to-native identification in the supplied note therefore conflicts with the native Lagrangian and executable chirality routing. A field-index transpose or a different source-to-native matching may resolve it, but neither is established by this test. The neutral map's claimed algebraic verification is insufficient for this interference, and the sign of the full source-to-frozen match also remains independently unverified. We have not altered or asserted an error in the frozen code.

An executable one-sided complex control sets only `D[e,mu]=0.3+0.4i`; Module4's neutral photon component returns C_L = `(2.9557097005730963e-7 + 3.940946267430796e-7 i)` and C_R = 0 for the explicitly artificial inputs in the test. Conjugate-transposing D moves the identical complex value to C_R. These are analytic control inputs, not Zee benchmarks. The source equation under the supplied map assigns the first input to c_R. This counterexample falsifies the combined mapping and routing assumptions; it does not establish which individual convention statement is wrong.
