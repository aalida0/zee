# Zee Type-II LFV: public literature and code reuse audit

**Date:** 2026-11-07. **Purpose:** identify the shortest, source-backed implementation route to lepton-flavor-violation constraints for a **standard charged-Higgs cascade phenomenology paper**. This is a targeted source/code audit, not an executed Zee comparison, a green LFV gate, or a fully exhaustive citation-graph search. Exact base research branch: `research/zee-full-constraints`. Original Modules0–13 and old production/scan data are unchanged.

## Decision up front

**Reuse the existing SARAH/FlavorKit-generated Wilson coefficients as the primary fixed-card starting point; use FlexibleSUSY NPointFunctions as an independent second generator after repairing versioned dependencies; use the corrected 2026 general-2HDM code for the transferable doublet-sector two-loop radiative decays; and use `flavio`/`wilson` or `MuonBridge` to cross-check low-energy rates.** No inspected public package is presently a *validated all-contributions, all-orders general Type-II Zee LFV plug-in*. That is not a claim none exists elsewhere.

Aim at the **minimum supported leading-contribution constraint set**, not a bespoke universal two-loop computation. A reduced set is legitimate for a scoped paper only after showing that omissions cannot reverse the chosen benchmark classifications, or explicitly labeling the corresponding exclusions as unassessed. In particular do not claim "all current LFV bounds" while `mu→e` conversion or dominant dipole pieces remain unknown.

## 4. One bounded execution proposal (NOT performed/authorized here)

Do **not** regenerate a new model, reproduce the full Zee neutrino mass, start another two-loop tensor calculation, or alter existing frozen SPheno physical spectrum.

1. **Dependency-only repair** in isolated user prefix: install official FeynArts≥3.10/FormCalc≥9.8; verify independent Mathematica `Needs[]`, exact file paths and version messages. There was **no Zee failure previously**. Pin both upstream hashes and FS commit.
2. **Four witness benchmark replay only**, existing D7/F13 NO/IO cards. Use existing SARAH physical masses/rotations/Yukawas. Request `BrLToLGamma`, `BrLTo3L`, and `LToLConversion` operators from NPointFunctions; preserve **individual scalar, vector, box, photon and chirality coefficients**, not only total rates. Compare to already generated SARAH/FlavorKit `Calculate*4L` routines. The first generation may reveal unsupported Zee model conventions; record as an environment/model adapter issue, not immediately physics missing.
3. **Explicit coverage accounting before rate:** inventory all diagram classes including internal W/Goldstone/ghost, γ/Z, charged F/D and neutral tree, check actual NPF `diagrams[...]` drop rules and `q²` approximations. Distinguish contributions whose *individual amplitudes* are suppressible by verified coupling/decoupling from those potentially leading. If gauge aggregate remains uncontrolled, no LFV PASS.
4. **Transfer only nonoverlapping 2026 corrected 2HDM doublet two-loop pieces**; compare their numerical effect relative to native one-loop and existing Barr–Zee at the same fixed cards; independently test 2HDM/zero-F/zero-mixing limits. Do not call the corrected general 2HDM calculation complete Zee.
5. **Two independent rate backends:** `flavio` 3-body and `flavio`+MuonBridge μ-e conversion. Map exactly named WET coefficients, renormalization scale, convention, units and chiral conjugation; one-operator and interference-level comparisons, validated against a published rate benchmark. The correction of a known source bug is not itself evidence that the remaining source is error-free.
6. **Decision gate:** produce a table with `BR`, sensitivity to omitted amplitudes, experimental limit, `PASS/FAIL/UNKNOWN` *per observable and witness*. Promote a physical veto only for genuinely covered channels. An attainable **scoped LFV set** may suffice for a paper **only with transparent stated omissions**, and must never be described as a globally flavor-allowed model point.

**Stop condition:** if dependency repair plus four-card generator comparison fails for a concrete architecture/model reason, write a minimal reproducible upstream issue/question to FlexibleSUSY (model setup and unphysical spectra detached), and keep old validated subsets. Do not initiate a new multi-month all-loop reimplementation. Our paper's novelty should be neutrino+flavor-informed charged cascade, not new loop topology formulae.
