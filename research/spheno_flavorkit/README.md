# ZeeTypeII SPheno / FlavorKit feasibility pilot

This is an experimental, **unvalidated** low-energy SPheno configuration. It is
isolated from the frozen model and Modules 0–14; it is not a D14 backend. See
[REPORT.md](REPORT.md) for actual results and open physics issues. Defaults are
only generation placeholders, not a benchmark.

## Reproduce the source-generation attempt

Requires licensed Mathematica 15.0.1, SARAH 4.15.4, GNU make, and gfortran.
On the tested system SARAH's archive had SHA-256
`4ab8f01ebe866cce954bc292118b5976913a2800efc6eeb2ad2e926a98fc42eb`.
From the repository root, run:

```sh
export SARAH_ROOT="$HOME/.Mathematica/Applications/SARAH-4.15.4"
research/spheno_flavorkit/generate.sh
```

The wrapper copies the **exact** three committed model files and this pilot's
`model/SPheno.m` into ignored `local/models/ZeeTypeII`; SARAH output and the
complete stdout/stderr transcript go to `local/output` and
`local/generation.log`. Run in a fresh checkout or move old local output aside
first: the wrapper does not clean it. `PILOT_START_PASS` means initialization
only; a zero kernel exit or `PILOT_MAKESPHENO_RETURNED` alone is not evidence
of complete valid generation. Inspect errors, generated files and completion.
The normal SARAH distribution includes pre-generated FlavorKit operator files;
PreSARAH's FeynArts/FormCalc are needed to derive new operators, not assumed
necessary for using its existing operators.

## Pinned user-space SPheno source

The official [SPheno project download](https://spheno.hepforge.org/downloads/SPheno-4.0.5.tar.gz)
provided the 4.0.5 archive on this machine. Its recorded SHA-256 is
`3f84a6c3e47f40e0dd1bcccb88eb08a1d0a65aa3d8e42504befdfc3d47ec9529`.
This records the retrieved bytes, not an independently verified publisher
signature. No root installation is needed:

```sh
mkdir -p research/spheno_flavorkit/local
cd research/spheno_flavorkit/local
curl -fL https://spheno.hepforge.org/downloads/SPheno-4.0.5.tar.gz -o SPheno-4.0.5.tar.gz
printf '%s  %s\n' 3f84a6c3e47f40e0dd1bcccb88eb08a1d0a65aa3d8e42504befdfc3d47ec9529 SPheno-4.0.5.tar.gz | sha256sum -c
# Continue only if the checksum matches.
tar -xzf SPheno-4.0.5.tar.gz
cd SPheno-4.0.5
make F90=gfortran > ../spheno-build.log 2>&1
```

SARAH writes generated files under `local/output/ZeeTypeII/EWSB/SPheno/`.
The stock defaults are not a validated benchmark; follow the reduced-build
procedure below. The candidate card does not establish full scheme matching.

## Reproduce the reduced build and exploratory benchmark

The default build generated by `generate.sh` fails as described in the report.
For the successful reduced variant, first run `generate.sh` to completion so
its analytic lists exist, then from the repository root:

```sh
SARAH_ROOT="$HOME/.Mathematica/Applications/SARAH-4.15.4" \
  math -script research/spheno_flavorkit/generate_lfv_only.m \
  > research/spheno_flavorkit/local/generation-lfv-only.log 2>&1
cp -a research/spheno_flavorkit/local/output/ZeeTypeII/EWSB/SPheno \
  research/spheno_flavorkit/local/SPheno-4.0.5/ZeeTypeII
(cd research/spheno_flavorkit/local/SPheno-4.0.5 && \
  make Model=ZeeTypeII F90=gfortran > ../zee-lfv-only-build.log 2>&1)
python3 research/spheno_flavorkit/benchmark_card.py \
  research/spheno_flavorkit/local/output/ZeeTypeII/EWSB/SPheno/Input_Files/LesHouches.in.ZeeTypeII \
  research/spheno_flavorkit/local/benchmark.in
(cd research/spheno_flavorkit/local && \
  SPheno-4.0.5/bin/SPhenoZeeTypeII benchmark.in benchmark.spc > benchmark.log 2>&1)
```

Copy into a fresh `ZeeTypeII` directory and use a fresh model library; stale
objects from the failed full build must not be mixed in. To reproduce the
complex dipole diagnostic, instrument only the ignored generated copy, rebuild,
and run the same card again from `local/`:

```sh
python3 research/spheno_flavorkit/instrument_dipole.py \
  research/spheno_flavorkit/local/SPheno-4.0.5/ZeeTypeII/Observables/LowEnergy_ZeeTypeII.f90
(cd research/spheno_flavorkit/local/SPheno-4.0.5 && \
  make Model=ZeeTypeII F90=gfortran > ../zee-instrumented-build.log 2>&1)
(cd research/spheno_flavorkit/local && \
  SPheno-4.0.5/bin/SPhenoZeeTypeII benchmark.in benchmark-instrumented.spc > benchmark-instrumented.log 2>&1)
```

The only instrumentation is two Fortran `Write` statements after coefficient
normalization. The script checks the insertion marker. The card preserves F
and Ye2 real/imaginary entries and enables `MODSEL 5 2`; this is an exploratory
card, not a fully matched EW/renormalization scheme. It intentionally disables
decay-width computation. `benchmark_card.py` requires NumPy and the existing
Module1 Python dependencies.
