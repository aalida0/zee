## Why F3 does NOT assign \`C4_bs\` to WCxf

F2 established EOS and flavio \(\Delta\mathrm{BR}\) consistency at the 0.64% level using the **same** E4A LO C7/C8 and wilson RGE, and identified a real NLO dipole effect. The NLO \(C_3,\ldots,C_6\) charged-Higgs matching cannot be inserted as \`C4_bs\` in \`WET/flavio\`, which rejects such an input. The WCxf \`JMS\` quark-current basis requires nontrivial operator flavor/color/Fierz normalization. It would be invalid to assign raw SuperIso \(C_4\) to an unrelated WCxf four-fermion operator or ignore its contribution while declaring full NLO.

F3 instead reuses the source-pinned **SuperIso 5.0** complete high-scale \`CW_calculator\` and **complete low-scale \`C_calculator_base1\`**, in the same convention, to evolve all operators. This avoids a guessed WCxf four-quark mapping, but it does **not** independently validate the SuperIso matching. The mixed high-scale coefficients are physical Zee-weighted:
\[
 C_i^{\rm Zee}(\mu_W)=C_i^{\rm SM}(\mu_W)
+\cos^2\gamma\,[C_i^{H_1}-C_i^{\rm SM}]
+\sin^2\gamma\,[C_i^{H_2}-C_i^{\rm SM}].
\]
Three controlled variants are evolved:
1. \`LO_RG\`: BSM \(C_i^{(0)}\) only; retain the same SM NLO/NNLO background high-scale values and full original RG evolution.
2. \`NLO_DIPOLES_RG\`: LO NP + source \(C_7^{(1)},C_8^{(1)}\) (and the perturbative RG mixing automatically generated by LO NP).
3. \`FULL_NLO_RG\`: LO NP + source \(C_3^{(1)},\ldots,C_8^{(1)}\), including *all source four-quark terms* through original NLO RG. This is a **matching-level completeness test only**. Source-pinned SuperIso v5 with isolated A1M NLO limiter fix; the original author/HEPfit independent NNLO basis discrepancies remain unresolved.

At \(\mu_b=4.2\) GeV the effective low-coefficient shift is evaluated in the vendor convention as \(\Delta C_i^{(0)}(\mu_b)+[\alpha_s^{(5)}(\mu_b)/(4\pi)]\Delta C_i^{(1)}(\mu_b)\). The low \(C_1\)–\(C_8\) vector is supplied directly to the independent EOS \`WET\` NLO observable through \`b->s::c1...c8\` parameter shifts—**never** through unsupported high-scale WCxf \`C4_bs\`. Because independent exact finite-renormalization/basis checks have not completed, each resultant EOS rate is labeled \`CONDITIONAL\`, not a validated physical NLO branching ratio.

## F3 v1 actual AF result and v2 order-resolved RG diagnosis

First **real** F3 source-based 27-spectrum and 64-Type-II run completed:
- \`Zee_spectra=27\`, \`typeII_dense_benchmarks=64\`, \`source_locked_TypeII_18_anchor_coefficients_checked=18\`.
- EOS conditional full-source-NLO BR range approximately \`3.8604–4.0501 × 10^-4\`.
- Original NLO C3–C6 four-quark *conditional* BR increment: median \`1.032765815e-8\`; maximum absolute \`1.233319930e-8\`. In the chosen vendor/EOS scheme this is around 0.003% of total BR, *not a basis-independent NLO uncertainty*.
- Cross-code maximum LO charged dipole RG mismatch \`6.5788%\`; F3 LO source-QCD evolution vs F2 \`wilson\`-RG EOS NP-rate mismatch \`6.6380%\`. These are **relative to the NP shift / Wilson coefficient**, not absolute BR. Previous 35% acceptance was deliberately a gross-error gate and is **not** precision validation.

A direct source audit of \`wilson/run/wet/classes.py\` shows the default \`qcd_order=1\` means **LO QCD ADM**. \`wilson/run/wet/rge.py\` explicitly evolves this LO QCD matrix; its default also includes leading QED running. The SuperIso \`C_calculator_base1\` is a multiorder QCD solution: even with **LO-only high-scale NP matching** it produces an induced NLO \`C1b\` contribution. Therefore comparing SuperIso \`delta C0b + alpha_s/(4pi)*delta C1b\` to \`wilson\` directly does **not** compare matching perturbative evolution orders. This is a **plausible cause**, but do not assert that it explains the full 6.6% before the decomposition below. QED/mass/coupling parameter differences and operator conventions are also possible.

EOS source \`eos/rare-b-decays/inclusive-b-to-s-gamma.cc\` explicitly defines
\`c7eff = c7 - c3/3 - 4c4/9 - 20c5/3 - 80c6/9\` and
\`c8eff = c8 + c3 - c4/6 + 20c5 - 10c6/3\`.
The source uses them internally: **EOS inputs must be raw low-scale \(C_i\), not pre-rotated \`C7eff\`,\`C8eff\`**, or the four-quark penguin rotation would be double applied. F3 prints both raw and effective candidates strictly as diagnostics.

The updated F3 v2 calculation now extracts the following **per point** from the same source-probe output with no matched source changes:
- \`LO_QCD_RG_ONLY\` using just the original \`delta C0b\` for the LO high-scale NP input;
- \`LO_RG\` using \`delta C0b + alpha_s(mu_b)/(4pi)*delta C1b\` **for that same LO input**;
- explicit NLO-running-induced \`deltaBR\` and each \(C_7,C_8\) difference;
- **separate** maximum relative low-WC and EOS-NP-rate discrepancies against \`wilson\` for the two evolution truncations.

This is an **order diagnostic**, not a complete order-matched NLO evolution validation; Wilson default LO still includes QED and uses its own inputs. A smaller LO-only discrepancy would support the perturbative-order hypothesis; unchanged discrepancies suggest coupling/mass/basis differences. Do not decrease a 35% pass threshold to 1% without ensuring equivalent QED schemes and matching normalization.

## F3 v3: isolate remaining 0.4% by switching leading QED evolution off in wilson

The F3 v3 code uses \`flavio.WilsonCoefficients.set_option("qcd_order",1)\` and \`set_option("qed_order",0)\` with **exactly the same** E4A LO C7/C8 high-scale inputs at 160 GeV, then runs to 4.2 GeV. It compares:

- SuperIso QCD LO-only low C7,C8 against \`wilson\` default QCD LO + QED LO (existing F3 v2).
- SuperIso QCD LO-only low C7,C8 against \`wilson\` QCD LO, **QED completely switched off** (new).
- Both low-scale vectors as inputs to EOS NLO \`deltaBR\`, recording the difference.

New maxima in \`F3_COHORT\`: \`max_relative_QCD_LO_only_C7_C8_source_vs_wilson_QED_OFF\` and \`max_relative_QCD_LO_only_RG_vs_wilson_QED_OFF_EOS_deltaBR\`. If these shrink well below 0.4%, leading QED running explains most of the remaining residual; if not, compare \(\alpha_s\), heavy-quark masses, matching/evolution scheme conventions (Wilson and SuperIso have different defaults).
